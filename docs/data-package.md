# Prepared data package

ABAP and eBird preparation write linked CSV tables, a `datapackage.json` descriptor, a manifest, and targeted audit files. The tables use common identifiers where their meanings agree. Original ABAP cards and eBird-derived candidate cards remain distinct, as do source detections and derived taxon presences.

```text
prepared-dataset/
├── cards.csv
├── records.csv.gz
├── species.csv
├── checklist.csv                  # eBird and combined outputs when present
├── pentads.csv                    # generated by source preparation
├── datapackage.json
├── manifest.json
├── excluded_observations.csv.gz   # eBird exclusions
├── audit.csv                      # ABAP mapping and card-merge decisions
└── audit/                         # eBird checklist and record provenance
    ├── checklist_members.csv.gz
    ├── checklist_quality.csv.gz
    └── record_sources.csv.gz
```

`datapackage.json` describes the columns and relationships of `cards`, `records`, `species`, and, when present, `checklist`. `pentads` and audit files are useful additional outputs and are not currently resources in the generated descriptor. Prepared files are local outputs; retain the source snapshot separately.

## Cards: `cards.csv`

One row is one original ABAP card or one derived eBird candidate. The key is (`source`, `card_id`). These shared columns appear first:

| Column | Meaning |
| --- | --- |
| `card_id` | Card identifier within a source; together with `source` identifies the card |
| `source` | `abap` for an original ABAP card; `ebird` for an eBird-derived candidate |
| `pentad_id` | Assigned pentad identifier |
| `observer_id` | Contributing observer IDs separated by `|` (older packages used a JSON array; `bird_atlas.card_schema.parse_observers` reads both) |
| `start_date`, `end_date` | `YYYY-MM-DD` dates; definitions differ by source as described below |
| `start_time` | Local time in `HH:MM:SS` when known |
| `duration_minutes` | Duration in minutes under the source's method |

For ABAP, dates and time come from the source card and reported total hours are converted to minutes. ABAP-specific columns retain protocol, observer name, per-hour fields, reported species count and habitat/night flags. An unparseable start time remains available in `unparsed_start_time`. For eBird, the start date is the card window's first day, the end date is the last included activity date, and the start time is the earliest included checklist start. Duration is qualifying, non-overlapping effort, blank for an ad-hoc card without any. eBird cards also carry `protocol`: `full` (at least two hours of qualifying effort) or `adhoc`. The methods and precision of the two sources are different.

## Records: `records.csv.gz`

The key is (`source`, `record_id`); each row references (`source`, `card_id`). `record_id` is unique within its source in the export but is not guaranteed stable across regenerated datasets.

| Column | Meaning |
| --- | --- |
| `ebird_avibase_id` | Mapped concept ID in the dataset's declared eBird reference; blank for an unresolved ABAP source taxon |
| `avibase_id` | Original source concept where known. For ABAP it comes from the curated crosswalk; eBird source concepts are retained individually in `audit/record_sources.csv.gz` |
| `source_spp` | Original ABAP `Spp` code; blank for eBird |
| `taxonomy_status` | Mapping or regional-override status |
| `sequence` | Source ABAP sequence when available; blank for eBird candidate presences |

**Record grain differs:** ABAP records retain source detections after cross-protocol duplicate handling. eBird records are one mapped taxon presence per card, for every taxon category. A combined dataset retains these different grains; it does not make them equivalent. The manifest identifies each source's grain. eBird observations excluded from taxonomy matching remain in `excluded_observations.csv.gz` rather than being assigned a guessed ID.

## Species: `species.csv`

One row represents a resolved taxon in the declared eBird reference, keyed by `ebird_avibase_id`. Columns include `scientific_name`, `common_name`, `category`, `ebird_species_code`, `ebird_taxon_order`, `report_as`, `parent_spp`, and `parent_avibase_id`. Names and classification come from the selected eBird reference.

In the current output, `report_as` is the **eBird Avibase ID** of the reporting taxon when it differs from the row's own taxon ID; otherwise it is blank. Reporting taxa are included even when they have no records, including every parent in a reporting chain. For ABAP, `parent_spp` and `parent_avibase_id` are JSON arrays of contributing source codes and source concepts. For eBird they are empty arrays. Combined exports omit these source-specific parent columns; consult the source datasets for them.

## Original eBird checklists: `checklist.csv`

One row links an original eBird submission to a card; the key is (`checklist_id`, `card_id`). `checklist_id` identifies the individual submission. `checklist_group_id` contains the shared group ID when it differs and is blank for an unshared checklist. To group independent activities, use `checklist_group_id` when present and `checklist_id` otherwise.

Rows include the source observer, date and time, duration, distance, protocol, completeness, reported coordinates, and `card_effort_eligible`. Shared submissions represent one activity: do not sum their durations or distances as independent effort. Card effort counts eligible activity within five calendar days of the card start, merges overlapping intervals, and counts each shared activity once. The individual durations and distances here are the reported values, not necessarily the amount counted within a card window.

## Pentads and audit files

`pentads.csv` is a convenience table with `pentad_id`, centre latitude/longitude, west/south/east/north bounds, and full WGS84 cell `area_km2`. It is generated by source preparation; the shared pentad functions can derive these properties from the ID. A combined export does not currently write a pentad table.

For eBird, `audit/checklist_members.csv.gz` preserves source membership, `audit/checklist_quality.csv.gz` records independent-event screening, the event's `CARD` and, if it joined none, its `UNASSIGNED REASON`, and `audit/record_sources.csv.gz` links each derived record to its source checklist, shared group, scientific name, and original `avibase_id`. The record table leaves eBird `avibase_id` blank because a card–taxon presence can aggregate multiple original IDs. These source associations prevent loss of that detail.

The disk-backed exporter writes compact `excluded_observations.csv.gz` rows at the same collapsed event–taxon grain. These contain the original checklist/observer, original `avibase_id`, scientific name and category, representative checklist, JSON membership lists, shared-conflict flag, and an explicit exclusion reason. Use the linked member/quality audits for effort metadata and the original source or reusable cache for observation detail. Unlike the previous wide exclusions table, this file does not repeat null reference columns and all checklist metadata on every excluded taxon.

For ABAP, `audit.csv` contains card-merge details, conflicts, and taxonomy issues including unresolved or provisional mappings and regional overrides. ABAP `avibase_id` records the crosswalk's source concept where available, rather than an ID invented from a missing source field.

## Manifest, combination and validation

`manifest.json` records source identity, input and taxonomy provenance, selected policy and record grain. The ABAP manifest also records its snapshot, regional assumptions and crosswalk inputs. Preserve the original prepared datasets and audits alongside any combined dataset: combination currently copies the shared tables and eBird checklist table, but does not copy source audit directories or a pentad table.

To combine prepared datasets, use matching declared eBird versions and the same exact reference file. The script checks reference provenance and rejects conflicting taxon fields or duplicate keys within a source. It does not implement cross-version taxonomic harmonization. Its output records the inputs and their source grains.

```sh
uv run python scripts/shared/combine.py /path/to/prepared-abap /path/to/prepared-ebird --output /path/to/combined
uv run python scripts/shared/validate.py /path/to/combined
```

Validation checks the data-package descriptor, required shared fields, keys, foreign-key relationships and supported sources. It does not prove that taxa are scientifically equivalent or that card locations, identifications or effort are accurate. See the [ABAP](abap-to-ebird.md) and [eBird](ebird-preparation.md) guides for source-specific preparation and limitations.
